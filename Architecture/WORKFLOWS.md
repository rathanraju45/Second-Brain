# Core Workflows

# Primary Workflow

```text
Capture
→ Inbox
→ Process
→ Organize
→ Execute
→ Review
→ Archive
```

---

# Capture Workflow

Purpose:
- Minimize friction
- Capture quickly
- Organize later

Rules:
- Everything defaults to Inbox
- Direct capture is allowed when destination is obvious
- Capture should require minimal thinking

Capture Types:
- Tasks
- Ideas
- Notes
- Links
- Research
- References

---

# Inbox Processing Workflow

```text
Inbox Item
    ↓
Identify Type
    ↓
Move to Proper System
```

Possible Destinations:
- Projects
- Tasks
- Notes
- Resources
- Archives

---

# Project Workflow

```text
Project Created
→ Planning
→ Active Execution
→ Review
→ Completion
→ Archive
```

Projects may contain:
- Tasks
- Notes
- Resources

Projects act as operational centers.

---

# Task Workflow

```text
Task Created
→ Prioritized
→ Scheduled
→ Executed
→ Completed
→ Archived
```

Tasks primarily support projects.

Independent tasks are allowed temporarily.

---

# Knowledge Workflow

```text
Capture
→ Process
→ Refine
→ Organize
→ Reuse
```

Knowledge should:
- remain reusable
- remain searchable
- stay independent from projects

Projects may reference knowledge.

---

# PARA Workflow

## Projects
Active initiatives.

## Areas
Long-term responsibilities.

## Resources
Reference material.

## Archives
Inactive or completed items.

---

# Review Workflow

## Daily Review
- Check active tasks
- Review priorities
- Process inbox

---

## Weekly Review
- Review projects
- Clean unfinished tasks
- Reorganize knowledge
- Plan next actions

---

# Archive Workflow

Items are archived when:
- completed
- inactive
- no longer actionable

Archived items remain searchable.
