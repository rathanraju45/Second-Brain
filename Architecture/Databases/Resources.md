# Resources Database

# Purpose

Stores external references and supporting material used for:
- learning
- projects
- research
- knowledge building

Resources act as reference infrastructure.

---

# Responsibilities

Resources are responsible for:
- preserving useful references
- organizing external material
- supporting projects and notes
- reducing repeated searching

---

# Core Principles

- Resources are references, not knowledge itself
- Resources support learning and execution
- Resources should remain searchable
- Resources should stay lightweight

---

# Examples

- Articles
- Documentation
- Tutorials
- Videos
- Tools
- Repositories
- Research Papers

---

# Essential Properties

| Property | Type | Purpose |
|---|---|---|
| Title | Title | Resource name |
| Type | Select | Article / Video / Tool / Repo / Documentation / Research |
| URL | URL | External link |
| Projects | Relation → Projects | Related projects |
| Notes | Relation → Notes | Related knowledge |
| Areas | Relation → Areas | Related domain |
| Status | Select | Unprocessed / Active / Archived |
| Tags | Multi-select | Flexible categorization |
| Archived | Checkbox | Archive state |

---

# Resource Philosophy

Resources should:
- reduce information loss
- reduce repeated searching
- support future reuse

Avoid:
- saving everything
- excessive bookmarking
- low-value accumulation

---

# Dashboard Role

The dashboard may surface:
- active learning resources
- project references
- recent captures

Resources should remain secondary to execution systems.

---

# Archive Philosophy

Old or inactive resources may be archived while remaining searchable.

---

# Design Notes

Resources are reference systems, not operational systems.

Their purpose is to:
- support thinking
- support execution
- support learning

without overwhelming the core workflow.
