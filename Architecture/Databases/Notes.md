# Notes Database

# Purpose

Stores reusable knowledge, thinking, and long-term intellectual assets.

Notes are designed to:
- preserve knowledge
- support learning
- assist projects
- enable future reuse

---

# Responsibilities

Notes are responsible for:
- capturing ideas
- storing insights
- documenting learning
- preserving research
- connecting knowledge

---

# Core Principles

- Knowledge should remain reusable
- Notes should exist independently
- Notes may reference projects
- Notes are long-term assets

---

# Essential Properties

| Property | Type | Purpose |
|---|---|---|
| Title | Title | Note title |
| Type | Select | Idea / Concept / Research / Documentation / Reference |
| Status | Select | Fleeting / Permanent / Archived |
| Created | Created Time | Creation tracking |
| Projects | Relation → Projects | Optional project linkage |
| Areas | Relation → Areas | Related responsibility domain |
| Resources | Relation → Resources | Supporting references |
| Tags | Multi-select | Flexible categorization |
| Archived | Checkbox | Archive state |

---

# Suggested Knowledge Flow

```text
Capture
→ Process
→ Refine
→ Organize
→ Reuse
```

---

# Relationships

## Projects
Notes may support projects.

Projects should not own knowledge permanently.

Knowledge remains independent.

---

## Resources
Notes may reference:
- articles
- documentation
- tutorials
- external material

---

## Areas
Notes may belong to long-term domains of responsibility.

---

# Knowledge Philosophy

Notes are not:
- temporary dumps
- project-only documents
- isolated text blocks

Notes should evolve into reusable knowledge assets.

---

# CODE Integration

The Notes system supports the CODE methodology:

```text
Capture
→ Organize
→ Distill
→ Express
```

---

# Dashboard Role

The dashboard may surface:
- recent notes
- active research
- project-related knowledge
- learning feeds

The dashboard should not expose the entire knowledge base at once.

---

# Archive Philosophy

Old or inactive notes may be archived while remaining searchable.

Knowledge history should remain preserved.

---

# Design Notes

The Notes database is one of the foundational long-term systems of the architecture.

Unlike tasks or projects:
- knowledge compounds over time
- reusable thinking increases system value
- notes become intellectual infrastructure
